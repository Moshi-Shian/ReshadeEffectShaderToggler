# REST Enhanced v1.6.8.580 — Legacy

D3D9 compatibility and general resource-lifecycle maintenance for Legacy ReShade 5.8–5.9.2 / API 7.

- Accept standalone D3D9 surface render targets where a texture target was previously required. Standalone surfaces do not gain texture sampling, Automatic Scene Colour or modern HDR presentation.
- Release REST-owned D3D9 views, group buffers, previews and shader resources before the last runtime on a device is destroyed for Reset. Preserve shared resources while another runtime on that device remains.
- Release views before their backing resources and make view cleanup safe to repeat.
- Separate cached texture views by device, resource handle and typed format; choose a replacement runtime from the same device.
- Keep removed group objects alive for outstanding CPU queues, mark retirement before cleanup and skip retired work. Retained CPU objects are freed at add-on teardown; owned GPU buffers follow the synchronized cleanup path.
- Evaluate pixel, vertex and compute effect queues independently so an earlier successful stage cannot skip later stages.

D3D9/reset and removed-group changes are adapted from BadassBaboon's fork, which credits CrazyDaifu for the D3D9 contribution. Attribution and the fork's MIT notice are included.

## Validation and scope

The release candidates are prepared from the maintained stable branches. They exclude the experimental D3D12 scene-input renderer, Warframe compositor/shader patching, DXC integration and scratch-image pools. They do not claim to resolve issue #22.

Native local D3D9 checks exercise the production view class through a small ReShade API host, in x86 and x64: standalone surfaces, texture RTV/SRV ownership, exact pixel readback, repeated cleanup and 24 successful resets per architecture and SDK line. These tests do not load the complete add-on into a game. Production group/view lifecycle tests, rendering-safety checks, both native builds, package/workflow regressions and binary validation accompany the candidates. A native D3D9 test may explicitly skip on a CI runner without a HAL device; this does not replace the successful local coverage.

**Candidate status:** representative game-level D3D9 reset/hunting/effect checks and fresh backend smoke tests remain required before stable publication. Record actual coverage using [Maintenance release validation](../maintenance-release-validation.md). Do not interpret successful compilation or a standalone GPU test as proof of every game configuration.
